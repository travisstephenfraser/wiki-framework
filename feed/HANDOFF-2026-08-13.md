## Key decisions — do not relitigate

**1. Do not perform the 48-commit merge.**
No benefit was ever articulated. A verifier grepped `docs/`, `feed/`, and the framework for a
rationale and found zero hits outside the plan document itself; the payload is weighted toward README
translations, `wiki-narrate`, and history-ingest skills for other agents. If revisited, cherry-pick
only `5016cde` + `95424e4` (cache), `9c260f7` (packaging), `14bdb41` — and **decline `2363445`**
(`strict_trust` duplicates the fork's own `WIKI_SCHEMA_PHASE` gate).

**2. Keep `WIKI_SCHEMA_PHASE`; do not migrate to upstream's knobs.**
They govern different surfaces. The phase variable has **zero Python readers** and gates what
write-skills *emit*; upstream's knobs parameterise the validator and gate what it *reports*. Not
duplicates.

**3. Stop hardening `vault_fingerprint.rb`. Gate on git instead.**
Four rounds kept finding new classes of "reports IDENTICAL while data is damaged." The deepest:
**git object-store destruction is invisible to it** — while git is the actual rollback path. The
vault is a git repository, so the correct gate is four battle-tested commands with none of those
holes:

```bash
git -C "$VAULT" status --porcelain          # tracked content unchanged
git -C "$VAULT" rev-parse HEAD              # position
git -C "$VAULT" fsck --connectivity-only    # object store intact  <- the hole the tool had
sha256sum ~/Developer/.vault/.raw-backup-*.tar.gz   # the gitignored remainder
```

The detector's remaining value is the readable field-level report *when something did change*. That
is a diagnostic, not a gate.

## Hazards — read before touching the framework

- **Never run `obsidian-wiki setup`.** Post-merge it scaffolds 11 vault directories, wires git sync
  (`init`/`add -A`/commit/**push**), and **clobbers `~/.obsidian-wiki/config`**, silently dropping
  `WIKI_SCHEMA_PHASE`. Three things push you toward it: a staleness nag, a bogus "34 skills missing"
  warning, and habit. The warning is a **measurement bug** — `setup.sh` deliberately installs a
  2-skill subset while `cli.py` declares all skills for the same path.
- **Treat `tier` as frozen.** It is gated by `WIKI_SCHEMA_PHASE` but is **not** in
  `_VOLATILE_CONFIDENCE_KEYS`, so it is hashed into `page_fingerprint`. Any phase-driven change to
  `tier` presence silently voids all 44 human trust approvals, hard-fails under strict, and has no
  escape hatch (`tier` is rejected by both the env var and the CLI flag).
- **`_raw/` is the least protected data in the system** — gitignored, untracked, skipped by lint and
  trust-check, and the one directory the framework documents itself as deleting from. Backed up
  2026-08-09 to `~/Developer/.vault/.raw-backup-2026-08-09.tar.gz`.
